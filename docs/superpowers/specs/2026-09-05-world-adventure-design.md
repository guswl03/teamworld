# TeamWorld: 마을 탐험과 월드 채팅

## 목표와 범위

기존 이동·접속·상태 기능을 유지하면서 마을의 시각적 다양성, 짧은 탐험,
외형 보상, 실시간 전체 채팅을 추가한다. 사용자가 제안된 RPG 확장에 채팅을
추가 요청했다. 이 문서는 구현 전 검토용이며 구현 완료를 의미하지 않는다.

첫 플레이 흐름: 안내 NPC 대화 → 퀘스트 수락 → 명소 탐험 → 보물 획득 →
NPC에게 완료 보고 → 모자 보상 착용. 채팅은 퀘스트와 무관하게 사용 가능하다.

## 구성과 경계

- 기존 Phaser 월드: 길드별 건물·정원·작업 도구 차별화, 시장 가판대·표지판,
  물결·굴뚝 연기·반딧불. 장식으로 길과 출현 위치를 막지 않는다.
- 탐험 모델: NPC와 명소 좌표, 퀘스트 3개, 순차 진행·완료·보상 상태를 순수 함수로 관리한다.
- 탐험 UI: 대화창, 목표 목록, 보물 획득 알림, 인벤토리와 모자 착용/해제.
- 기존 GameCanvas/WorldController 경계: 근접 상호작용과 로컬 외형 상태를 전달한다.
- 채팅 모델/컴포넌트: 입력 검증, 중복 제거, 최근 메시지 목록, 전송 상태.
- 기존 Transport 경계: 이동과 별도의 채팅 송수신 메서드·콜백을 추가한다.
  데모는 BroadcastChannel, 로그인 월드는 기존 private Supabase 채널을 사용한다.

## 탐험과 저장

안내 NPC에게 첫 퀘스트를 수락하고 지정 명소 3곳을 방문한다. 두 번째는
지정 보물상자를 근처에서 열기, 세 번째는 안내 NPC에게 돌아와 보고하기다.
완료한 퀘스트는 중복 보상을 지급하지 않는다. NPC 대화와 상자 열기는 근접 시
E 또는 화면 버튼으로 실행하며 대화 중에는 이동 입력을 막는다.

진행과 외형은 버전·월드·프로필별로 분리된 브라우저 저장소에 보관한다.
잘못된 저장값은 검증 후 기본 상태로 복구하고, 저장소가 차단되면 메모리에서
진행하되 새로고침 후 유지되지 않음을 안내한다. 최초 버전의 보상은 본인 화면에
표시하는 로컬 체험이며 다른 기기나 동료에게 동기화되는 영구 아이템이 아니다.

## 채팅 동작

- 현재 월드에 접속한 사람끼리 사용하는 전체 채팅 한 개를 제공한다.
  길드 전용 채팅·귓속말·파일 첨부는 제외한다.
- 닉네임과 수신 시각을 표시하고 메시지를 일반 텍스트로만 렌더링한다.
  HTML 실행과 자동 링크 변환은 하지 않는다.
- 한 메시지는 공백 정리 후 1~200자로 제한한다. 전송 간격은 최소 1초다.
  수신에서도 길이·형식·월드·현재 참가 세션을 검사하고 중복 ID를 제거한다.
- 접속 중 수신한 최근 100개만 메모리에 유지한다. DB에 저장하지 않으며
  새로고침·재입장·연결 중단 사이의 기록을 복원하지 않는다. UI에 이를 명시한다.
- 연결 중/끊김에는 전송을 막는다. 전송 결과가 실패면 입력을 보존하고 실패 안내를
  표시한다. 전송 성공 표시는 전원 수신이나 읽음 확인을 의미하지 않는다.
- Enter 전송, 한글 조합 중 Enter는 전송하지 않음, Escape 입력 포커스 해제.
  입력·대화 UI에 포커스가 있을 때 WASD·방향키·E가 월드에 전달되지 않는다.
- 새 메시지는 사용자가 목록 하단에 있을 때만 자동 스크롤한다.
  모바일에서도 메시지 확인과 입력이 가능하며 캔버스 미표시는 유지한다.
- 데모 채팅은 같은 브라우저의 같은 출처 탭 사이만 연결된다.
  서로 다른 PC의 채팅은 Supabase 설정과 실제 로그인 검증이 필요하다.

## 신뢰와 제한

기존 private 월드 채널의 접근 제어를 유지한다. 클라이언트가 제공하는 세션·닉네임
정보와 전송 제한은 서버 수준의 신원 보증이나 남용 방지가 아니다. 따라서 최초
채팅은 초대된 신뢰 구성원용이며 공개 익명 채팅으로 확장하지 않는다. 서버 검증,
신고·차단·관리 도구, 영구 기록은 별도 설계가 필요하다.

## 제외 사항

실제 전투, GitHub 업무 연동, 글로벌 경험치 경쟁, 다른 기기 간 아이템 동기화,
아이템 거래, DB 마이그레이션, 배포, 커밋 및 푸시는 이번 구현에 포함하지 않는다.
새 프로덕션 의존성을 추가하지 않는다.

## 검증과 완료 조건

- 퀘스트 순서·근접 판정·보상 중복 방지·저장값 복구 단위 테스트.
- 채팅 길이·빈 입력·잘못된 패킷·중복 메시지·전송 제한 테스트.
- 데모 두 클라이언트의 송수신·월드 분리·종료 후 미수신 테스트.
- 브라우저에서 한글 조합 입력, 이동키 간섭 없음, 두 탭 채팅, 연결 끊김,
  퀘스트 3개 완료·착용·새로고침 복원, 모바일 채팅 확인.
- 기존 테스트, 타입 검사, 포맷 검사, 프로덕션 빌드 실행.
- 기존 이동·충돌·카메라·상태·재접속 동작을 유지한다.
- 실제 Supabase 환경에서 검증하지 못한 항목은 완료 보고에서 구분한다.

## 설계 자체 검토

퀘스트/외형은 로컬 저장, 채팅은 휘발성 공유 데이터로 분리했다. 영구 저장이나
서버 권한 판정이 필요한 기능은 제외했다. 미정 필수 요구사항과 구현 자리표시자는
없으며 사용자의 설계 확인 후 구현 계획과 테스트부터 진행한다.
